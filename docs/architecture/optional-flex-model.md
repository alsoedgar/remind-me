# Optional flexible language pack

## Purpose

The required app remains useful, private, and fully offline with deterministic rules plus the bundled project-owned RemindCore and RemindSpeak models. RemindCore supplies confidence-gated calendar intent and source-copy evidence; RemindSpeak varies phrasing around already verified facts. Both were designed for this project, start from zero initialization, and import no pretrained weights. Their current v0.3 checkpoints retain explicitly audited Qwen teacher data for delexicalized wording or preference indices, but installed student inference remains independent of Qwen. They are the default product path, not adapters around the optional model.

The same locally installed pack may be used by developers as an offline teacher. That path receives protected synthetic prompts rather than personal calendars, has no student-weight access, and writes only raw proposal logs. Deterministic curation, disjoint challenge splits, original-test regression guards, and the native pipelines decide what affects RemindCore or RemindSpeak. This is data/preference distillation, separate from the optional runtime fallback described below.

Users who want more general conversation, harder paraphrases, and broader multi-intent language coverage may explicitly install `Qwen3-1.7B-Q4_K_M.gguf`. The 1.7B Q4_K_M quantization is a deliberate capability/footprint middle tier for consumer hardware. It requires substantially more disk, memory, and CPU time than RemindCore or RemindSpeak, so the app never treats it as required. The pack is not bundled and is never downloaded during startup, packaging, tests, or ordinary first-party-model use.

For calendar planning, the constrained system prompt defines supported operation meanings instead of relying on literal command verbs. It distinguishes creation, movement, rename/recurrence updates, duplication, deletion, reminder completion, and read queries; treats a greeting attached to a calendar request as part of that request; and requires every emitted source, title, and target to remain an exact request substring. Partial moves inherit the stored day, time, and duration when the user changes only one of them. A separate broad-language mode can answer general conversation from bounded recent turns, an extractive bounded conversation summary, explicit user-approved profile data, and compact verified calendar fact packets. Approved memories and derived conversation summaries remain separate inputs. The model has no database handle and cannot claim that a write occurred.

Multi-item fallback is message-scoped. The deterministic splitter first produces bounded, independently parseable clauses; if any clause still needs semantic help, the broker sends the complete semicolon-delimited batch to Qwen once rather than running one generation per item. The result is accepted only when it contains exactly one source-ordered action per clause and every action grounds back to that bounded batch. Clear native clauses keep their native parse, translated clauses are deterministically recompiled, and any unresolved item leaves the whole batch unstaged. Exact single spoken-clock forms such as “half past two in the afternoon” are recalculated from source text by deterministic code; an inaccurate model normalization is ignored, while alternatives such as “two or three” remain a clarification.

The pinned artifact is 1,282,439,264 bytes with SHA-256 `d2387ca2dbfee2ffabce7120d3770dadca0b293052bc2f0e138fdc940d9bc7b5`. Qwen3 1.7B is Apache-2.0 licensed. Remind Me streams the Q4_K_M GGUF from the fixed `ggml-org` Hugging Face conversion to a `.part` file, enforces the maximum byte count while downloading, hashes every chunk, and renames it atomically only after the exact digest and length match. The renderer cannot supply a URL or filesystem path.

## Isolation and resource policy

`node-llama-cpp` 3.20.0 is pinned with a portable CPU baseline and Metal on Apple silicon. Packaging removes unrelated architecture binaries. The normal Windows/Linux artifact stays CPU-only; an explicit release variant may retain Vulkan or CUDA on x64 while retaining CPU as a fallback. A generated backend manifest prevents runtime selection of an unshipped binary. The runtime selects Metal, CUDA, Vulkan, or CPU from that manifest, then chooses an automatic compact, balanced, or performance profile from available logical processors and live memory before a cold load. Users may force CPU but cannot request an unavailable backend. Every task receives a 4,096-token sequence; the performance tier spends the former 8K KV-token budget on two independent 4K sequences so planner and chat prefixes survive an alternating fallback. Lower tiers keep one shared sequence to avoid doubling cache memory.

Stable planner policy and examples now live in the planner system prefix instead of being resent as changing request text. Chat has a separate policy prefix and JSON grammar. Grammar objects stay cached for the process lifetime, input sections are fitted against the real Qwen tokenizer, and the current message, prioritized fact packet, recent turns, derived summary, and approved profile compete within an explicit token budget rather than overflowing the context. Fact packets are shortened only at complete fact boundaries, retaining review and focused facts before range and nearby facts. Planner output receives a 220–640-token cap based on request length and action cues. Chat normally receives a 192–224-token cap, with a hard maximum of 256: the response-content allowance follows the selected hardware profile and request depth, while the reserved margin lets the grammar close its verification envelope instead of producing partial JSON. A capped text value is reduced to its last complete sentence when possible.

Inference runs in an Electron utility process and executes one native generation at a time through a priority scheduler. Chat and calendar planning run ahead of queued document repair/fallback; active bounded document work cooperatively yields and resumes when foreground input arrives. Stream IDs provide queue identity and cancellation from renderer through IPC to the worker `AbortSignal`. Performance requests time out after 90 seconds; balanced and compact requests retain a 120-second allowance. The mmap-backed runtime uses a hardware-aware 30-second, automatic tier, or one-hour keep-warm policy, and live pressure can shorten the window. The integrity stream uses 4 MiB reads but still performs the complete pinned SHA-256 check once per application run before first inference. Calendar-plan inference starts only after the compact parser cannot safely classify a request; broad-language inference is used only when the pack is installed and enabled. Killing that process releases model memory without affecting SQLite or the renderer.

Settings reports the selected backend, thread count, per-task context, cache policy, idle window, and last bounded request metrics. These values are observability only: the renderer cannot choose unsafe runtime parameters or pass model paths.

Settings exposes install progress, enabled state, cancellation, and removal. The downloaded weight and a one-boolean state file live under Electron's per-user data directory. Disabling unloads the process; removal deletes only the pinned model and partial-download paths. Calendar data is not touched.

## Authority boundary

The model is an optional language tier, not a calendar authority. Its mutation path is deliberately narrower than its conversational ability:

The assistant broker exposes that boundary as two independent capabilities: `CalendarFallbackPlanner` returns a structured `plan`, `not-calendar`, or a typed runtime failure, while `GeneralFallbackResponder` returns a structured `answer`, `clarification`, `offline-limit`, or `refusal` envelope, or a typed runtime failure. Production wiring supplies the same isolated local runtime through both narrow interfaces, but callers cannot treat chat text as a plan. Missing, disabled, timed-out, unavailable, and invalid-output states remain distinct all the way to execution traces and user-facing limitations; `null` is retained only inside the legacy compatibility adapter.

1. A generation grammar permits one to eight classified actions and nullable title/target excerpts. A split mutation batch receives at most one planner generation and requires exact action cardinality.
2. Every `sourceText`, `titleText`, and `targetText` must be an exact contiguous substring of the bounded canonical request. Invented or overlapping excerpts reject the entire result; the untouched original remains the persisted conversation and proposal source.
3. The existing deterministic parser reparses each excerpt with the bounded operation hint.
4. Existing entity retrieval, date/time/recurrence resolution, risk policy, and dry run must all succeed.
5. Multiple mutations become one review proposal, one SQLite transaction, and one undo record. Any invalid item prevents the complete batch from being staged.
6. The model never receives a database handle, mutation IPC, arbitrary file path, calendar-write method, or network tool. Its conversational output is text only and cannot commit or confirm a calendar action.

Conversational calendar facts use short request-local references such as `F1` plus stable fact and entity IDs, per-field values, occurrence time, priority, and provenance. Qwen must put every calendar value in a declared placeholder and return the matching fact ID and field list. The broker checks the envelope, reference/ID pair, field availability, placeholder use, direct copied values, unverified time/date/location/status literals, and calendar-write language before rendering any text. It substitutes verified values locally and derives related entity links itself. Invalid text is discarded without reaching the renderer or changing state. Open-ended replies with no calendar fact packet use the worker's real cumulative token callback with a two-word safety lag; a prefix that forms a calendar-write claim is never forwarded. Calendar-factual replies remain hidden until the complete reference envelope passes validation, then the renderer receives only the locally substituted verified text. Typed queue/loading/generating/validating phases keep the thinking state accurate before text is safe to show.

Calendar-routed language reaches the structured planner only after the contextual resolver, deterministic parser, and RemindCore advisory path need help. A `not-calendar` result may hand a non-mutation turn to the general responder. Calendar mutations never make that handoff: planner failure produces a clarification or explicit limitation, leaves the active calendar snapshot unchanged, and stages no proposal. Broad conversation goes directly to the responder and cannot enter calendar planning merely because a response sounds imperative.

If installation, integrity verification, process startup, inference, JSON validation, grounding, or deterministic recompilation fails, Remind Me keeps the first-party/rules result or returns a focused clarification or honest local limitation. No partial model output is applied.

Broad phrasing is a coverage goal, not a promise that every sentence is unambiguous or that a 1.7B quantized model matches a hosted frontier model. The assistant asks a focused question when it cannot identify an item, date, time, recurrence scope, or destructive intent safely. The optional model can make the experience more flexible and personable, but it never receives direct calendar control and cannot bypass deterministic compilation, dry run, review, confirmation, or atomic execution.

For non-calendar conversation, a response generated without a calendar fact packet cannot have a
valid calendar reference. The worker therefore removes model-invented reference metadata only when
the returned prose contains no fact placeholders; placeholder-bearing output still fails closed.
An `offline-limit` envelope is displayed as a useful answer with an explicit offline limitation,
not as a generic unsupported dead end. Phase 7 binds the worker, prompts, structured schemas, model,
and synthetic quality suite to one real-model report, then applies compact, balanced, or performance
latency/first-token/RSS budgets without mixing those numbers into the sub-100 ms native gate.
