# Remind Me product and engineering audit

Audited September 5, 2026. Base commit: `80da4b3`; findings include the working tree at review time. Existing edits in App.tsx, app.css, the parser/router, and assistant service/tests were preserved. Line numbers below refer to that snapshot and may move.

Remind Me has a strong local calendar engine and carefully bounded model integration. Its biggest opportunity is to make the existing features dependable and discoverable, then add a provider-independent conversation and integration layer. Replacing the deterministic calendar engine or training a general chat model from scratch would be poor first investments.

The deliverables are this audit, the [implementation plan](../plans/2026-09-05-remind-me-improvement-plan.md), and the [integration feasibility decisions](../plans/2026-09-05-integrations-feasibility.md). These are plans, not implemented features.

## Model capability assessment

RemindCore and RemindSpeak are useful specialists. Their implementation uses classification heads and protected response selection, respectively; they are not substitutes for a general autoregressive chat model. Keep them for fast offline intent recognition and verified calendar answers. Add broader reasoning through a separate interchangeable provider, while keeping all writes behind the existing validated proposal and transaction boundary.

The current local chat uses short, bounded history and a 4K model context, with approximately 192–256 output tokens available depending on profile. These constraints suit short calendar assistance much better than sustained discussion, document questions, or lengthy explanations.

The [existing contextual Phase 7 report](../evaluation/assistant-contextual-phase7.md) records warm chat p95 **41.852 seconds**, first-token p95 **29.810 seconds**, and raw task quality **83.3%** on one Windows CPU reference machine. Those are historical measurements, not benchmarks rerun in this audit. Strong synthetic safety results do not establish broad conversation quality. Independent human evaluation is documented as pending, with zero participants/scenarios collected at that checkpoint.

The highest-value improvements are provider abstraction, streaming, cancellation, coherent context management, read-only calendar/document retrieval, a usable conversation history UI, and realistic evaluation. Model selection should follow measurements on those tasks instead of a permanently hard-coded model name.

## Document and calendar scope

The current document contract accepts PDF, PNG, JPEG and WebP. Bounds include 25 MiB, 20 pages, 25 million image pixels, 12,000 words, 200,000 characters and 50 proposals. It is a schedule extraction workflow, not arbitrary visual question answering. See [document-api.ts](../../packages/contracts/src/document-api.ts), lines 18–27 and 103.

“Any picture or PDF” should become a clear intake promise: accept supported uploads; detect and explain limitations; convert additional formats where possible; allow questions and summaries even when no event exists; extract events only from attributable evidence. It should not promise perfect handwriting, corrupted-file recovery or unlimited pages.

Canvas currently imports selected assignment due dates through a read-only token connection. It is not a continuously synchronized personal calendar. ICS file import, subscribed feeds, API read sync, and two-way event sync are separate capabilities and need different user expectations, identity models and failure handling.

## Recommended first release boundary

Resolve A01–A09 before expanding the affected flows, including explicit handling of unsupported ICS features. Then ship simpler settings, reliable alerts, richer reminder workflows and one online chat adapter. Add calendar subscriptions only after external identity and recurrence behavior are trustworthy. Prototype ChatGPT sign-in in parallel as a bounded feasibility experiment; do not make the offline app depend on it.

Preserve the existing model-to-proposal-to-review-to-transaction boundary throughout. Update [the privacy inventory](../privacy/data-inventory.md) before online chat or retained attachments ship: it currently contains unconditional upload exclusions and treats integrations as future work, while Canvas already exists.
